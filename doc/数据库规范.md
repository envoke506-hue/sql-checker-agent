# 数据库规范

## 命名规范

db\_order.order


|     |      |            |
| --- | ---- | ---------- |
| id  | code | sender\_id |
| ... | ...  | ...        |

1. 采用 lower\_snake\_case 命名法
2. 在语义明确的情况下尽量简短
3. 外键关系采用 表名\_字段 的命名方式
4. 单价的统一命名后缀为 \[xxxx\_\]price，如：price, order\_price
5. 金额的统一命名后缀为 \[xxxx\_\]money，如：money, order\_money，remain\_money
6. 数量的统一命名后缀为 \[xxxx\_\]amount，如：amount, order\_amount，user\_amount
7. 时间的统一命名后缀为 \[xxxx\_\]time，如：update\_time，receive\_time，send\_time
8. 业务类统一命名前缀为 biz\_\[xxxx\]，如：biz\_type，biz\_id
9. 入口类统一命名前缀为 in\_\[xxxx\]，如：in\_store，in\_bill
10. 出口类统一命名前缀为 out\_\[xxxx\]，如：out\_store，out\_bill
11. 编号、编码相关的统一命名后缀为 \[xxxx\_\]code，如：vehicle\_code，user\_code
12. 数量含单位的字符字段统一命名后缀为 \[xxxx\_\]amount\_unit，该类字段仅作展示，不参与计算，如：order\_amount\_unit
13. 排序的统一命名 sort
14. 备注的统一全名 remark
15. 库前缀在无特殊情况统一使用 db\_
16. **若是本表自己的字段，字段前不需要加表名 如：order 表 order\_code, order\_name 应直接写 code, name**
17. 数量、金额类统一使用 decimal 类型，精确如无特殊需求统一使用 decimal(20, 6)，针对老系统在风险不可预知的情况下保持与原系统一致

## 建表规范

### 建库规范(详见MySQL规范)：

```plaintext
1、数据必须使用innodb引擎
2、表内禁止外键设计
3、禁止触发器、存储过程、自定义函数
4、字符集为：utf8mb4
5、研发操作生产库必须经过评审后方可操作
6、表与字段不允许用关键字  或者  看着像关键字的单词
7、DDL增加字段标注AFTER
8、数字类型已知不存在负数的情况下可以加 UNSIGNED 可使数值范围扩大一倍
9、尽自己的能力使用 NOT NULL 或 NOT NULL DEFAULT
10、大表不允许加字段，采用扩展表的方式实现，如果不得不加的情况下控制在低峰期操作
11、double类型不要用，直接用decimal
12、关联表以r_开
13、对于 TINYINT 类型，统一使用 TINYINT(4)，规避驱动对 TINYINT(1) 的特殊处理造成不同业务的语义分歧
14、关于建表结尾的字符集要求，由于历史的原故，可以不填，但如果填了必须是符合规范的字符集
```
