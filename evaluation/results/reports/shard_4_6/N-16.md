# N-16 · 数量金额使用 double / 低精度 decimal

- 案例类型：反例
- 所属模块：命名规范（01_naming.md）
- 违反条款：命名规范 17 —— 数量、金额类统一使用 `decimal`，无特殊需求统一 `decimal(20, 6)`；建库规范 12 —— `double` 类型不要用
- 期望命中规则：命名规范 · 金额数量精度、建库规范 · 禁用 double
- 期望级别：ERROR
- 依据切块：chunk_naming_rules、chunk_database_rules
- 执行状态：ok（耗时 13.41s，开始于 2026-10-16T15:13:56+08:00）

- 审查判定：不合规
- 合规得分：40
- 检出违规数：3
- 审查综述：表结构与基类字段基本合规，但金额/数量字段存在严重类型问题：order_money 使用 double、unit_price 使用 float 会造成精度丢失，goods_amount 使用 decimal(10, 2) 精度不足，均须改为 decimal(20, 6)。

## 整改回复 (markdown_report)

### ⚠️ 不满足项与整改方案（共 3 项）

**1. 禁止使用 double 类型** · 🔴 ERROR · 依据：[5] 《数据库规范》- 数据库规范 > 建表规范 > 建库规范
- 不满足片段：`order_money DOUBLE`
- 问题说明：金额字段使用 double，存在精度丢失风险，违反禁用浮点要求
- 整改方案：改为 DECIMAL(20, 6) NOT NULL DEFAULT 0

**2. 禁止使用 float 浮点类型** · 🔴 ERROR · 依据：[5] 《数据库规范》- 数据库规范 > 建表规范 > 建库规范
- 不满足片段：`unit_price FLOAT`
- 问题说明：单价字段使用 float，浮点运算精度丢失，须用 decimal
- 整改方案：改为 DECIMAL(20, 6) NOT NULL DEFAULT 0

**3. 数量金额统一使用 decimal(20, 6)** · 🔴 ERROR · 依据：[1] 《数据库规范》- 数据库规范 > 命名规范 > 规则清单与反例
- 不满足片段：`goods_amount DECIMAL(10, 2)`
- 问题说明：数量类字段精度不足，未使用规范要求的 decimal(20, 6)
- 整改方案：改为 DECIMAL(20, 6) NOT NULL DEFAULT 0
