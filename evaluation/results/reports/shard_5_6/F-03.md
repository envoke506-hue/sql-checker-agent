# F-03 · 普通索引未以 `idx_` 开头

- 案例类型：反例
- 所属模块：字段与索引（05_field_and_index.md）
- 违反条款：建表规范 3 —— 普通索引必须以 `idx_` 开头
- 期望命中规则：建表规范 · 普通索引 idx_ 前缀
- 期望级别：ERROR
- 依据切块：chunk_field_and_index_rules
- 执行状态：ok（耗时 13.1s，开始于 2026-10-16T15:17:36+08:00）

- 审查判定：不合规
- 合规得分：60
- 检出违规数：2
- 审查综述：基础基类字段、主键、金额类型与引擎字符集均合规，但两个普通索引命名未按规范以 idx_ 开头，需整改为 idx_user_id 与 idx_code。

## 整改回复 (markdown_report)

### ⚠️ 不满足项与整改方案（共 2 项）

**1. 普通索引必须以 idx_ 开头** · 🔴 ERROR · 依据：[2] 《数据库规范》- 数据库规范 > 建表规范 > 字段设计与索引命名
- 不满足片段：`KEY `index_user_id` (`user_id`)`
- 问题说明：普通索引名 index_user_id 未以 idx_ 开头，不符合索引命名规范
- 整改方案：索引名改为 idx_user_id

**2. 普通索引必须以 idx_ 开头** · 🔴 ERROR · 依据：[2] 《数据库规范》- 数据库规范 > 建表规范 > 字段设计与索引命名
- 不满足片段：`KEY `order_code_idx` (`code`)`
- 问题说明：普通索引名 order_code_idx 未以 idx_ 开头，且违背本表字段不加表名
- 整改方案：索引名改为 idx_code

### ✅ 修改后的 SQL
```sql
CREATE TABLE `db_order` (
  `id` BIGINT UNSIGNED NOT NULL COMMENT '主键',
  `code` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '订单编号',
  `user_id` BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '用户标识',
  `version` INT NOT NULL DEFAULT 0 COMMENT '数据版本',
  `deleted` TINYINT(4) UNSIGNED NOT NULL DEFAULT 0 COMMENT '删除标记 0: 未删除 1: 已删除',
  `disabled` TINYINT(4) UNSIGNED NOT NULL DEFAULT 0 COMMENT '停用标记 0: 未停用 1: 已停用',
  `create_id` BIGINT UNSIGNED NOT NULL COMMENT '创建人标识',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `modify_id` BIGINT UNSIGNED NOT NULL COMMENT '修改人标识',
  `modify_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '修改时间',
  PRIMARY KEY (`id`),
  KEY `idx_user_id` (`user_id`) USING BTREE,
  KEY `idx_code` (`code`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单表';
```
