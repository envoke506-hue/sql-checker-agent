# F-10 · 1 个整数的字段使用 `INT` 而非 `TINYINT(4)`

- 案例类型：反例
- 所属模块：字段与索引（05_field_and_index.md）
- 违反条款：建表规范 8 —— 1 个整数使用 `status TINYINT(4) NOT NULL DEFAULT 0`
- 期望命中规则：建表规范 · 单整数用 TINYINT(4)
- 期望级别：WARN
- 依据切块：chunk_field_and_index_rules
- 执行状态：ok（耗时 11.59s，开始于 2026-10-16T15:19:18+08:00）

- 审查判定：不合规
- 合规得分：60
- 检出违规数：2
- 审查综述：表名、主键、7 大基类审计字段与引擎字符集均符合规范，但 status 字段类型选择超出 1 个整数的 TINYINT(4) 要求，biz_type 未加 UNSIGNED，需按规范修正字段类型定义。

## 整改回复 (markdown_report)

### ⚠️ 不满足项与整改方案（共 2 项）

**1. 整数字段类型选择规范** · 🔴 ERROR · 依据：[2] 《数据库规范》- 数据库规范 > 建表规范 > 字段设计与索引命名
- 不满足片段：`status INT NOT NULL DEFAULT 0`
- 问题说明：1 个整数的状态字段应使用 TINYINT(4)，不得用 INT
- 整改方案：status 改为 TINYINT(4) NOT NULL DEFAULT 0

**2. 无负数数字类型必须加 UNSIGNED** · 🔴 ERROR · 依据：[5] 《数据库规范》- 数据库规范 > 建表规范 > 建库规范
- 不满足片段：`biz_type BIGINT NOT NULL DEFAULT 0`
- 问题说明：biz_type 不存在负数，未加 UNSIGNED 浪费一半取值范围
- 整改方案：biz_type 改为 BIGINT UNSIGNED NOT NULL DEFAULT 0

### ✅ 修改后的 SQL
```sql
CREATE TABLE db_order (
  id BIGINT UNSIGNED NOT NULL COMMENT '主键',
  biz_type BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '业务类型',
  status TINYINT(4) NOT NULL DEFAULT 0 COMMENT '状态，0：初始化 1：成功 2：失败',
  version INT NOT NULL DEFAULT 0 COMMENT '数据版本',
  deleted TINYINT(4) UNSIGNED NOT NULL DEFAULT 0 COMMENT '删除标记 0: 未删除 1: 已删除',
  disabled TINYINT(4) UNSIGNED NOT NULL DEFAULT 0 COMMENT '停用标记 0: 未停用 1: 已停用',
  create_id BIGINT UNSIGNED NOT NULL COMMENT '创建人标识',
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  modify_id BIGINT UNSIGNED NOT NULL COMMENT '修改人标识',
  modify_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '修改时间',
  PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单表';
```
